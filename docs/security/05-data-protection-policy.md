## Purpose

This policy defines how SellAssist classifies, protects, stores, retains, and deletes data — including seller personal information, marketplace-connected data, and product/listing data — consistent with data protection principles found in applicable privacy law and in marketplace partner data-handling requirements.

## Scope

Applies to all data processed by SellAssist regardless of source: data provided directly by a seller, data received from a connected marketplace, data generated by SellAssist's AI product-listing pipeline, and payment-related metadata. Applies across the full data lifecycle — collection, transmission, storage, use, sharing, and deletion.

## Definitions

| Term | Definition |
|---|---|
| **Personal Information (PI)** | Any data that identifies or could identify a natural person — e.g., name, email, phone number, GST registration number. |
| **Customer Data** | Data describing a SellAssist account holder and their use of the platform. |
| **Marketplace Data** | Data received from, or intended for publication to, a connected marketplace (Amazon, Flipkart, Meesho, Shopify, WooCommerce, or a future integration) — including marketplace-issued credentials/tokens, order data, and listing status. |
| **Product Data** | Listing content itself — product names, descriptions, images, pricing, category, HSN/tax codes, and AI-generated marketplace copy. |
| **Data Controller** | The entity that determines the purpose and means of processing personal data — SellAssist, with respect to seller account data. |
| **Data Processor** | An entity that processes data on behalf of a controller — e.g., SellAssist's hosting or email-delivery providers, with respect to data SellAssist instructs them to process. |
| **Retention Period** | The length of time data is kept before deletion or anonymization. |

## Policy

### 1. Data Classification

All data handled by SellAssist is classified into one of four levels, which determines the controls required in the sections that follow:

| Level | Definition | Examples |
|---|---|---|
| **Restricted** | Highest sensitivity; compromise creates direct, severe harm. | Password hashes, password-reset/email-verification tokens, marketplace API credentials/OAuth tokens, payment processor secrets. |
| **Confidential** | Personal or business-sensitive data; compromise creates meaningful harm. | Seller name, email, phone number, GST number, order/sales history, uploaded product images not yet public. |
| **Internal** | Operational data not intended for public release, low individual harm if disclosed. | Application logs, internal usage analytics, non-sensitive configuration. |
| **Public** | Intended for public visibility. | Published marketplace listings, public-facing marketing content. |

Handling requirements scale with classification: Restricted data receives the strictest controls in every section below (encryption, access, retention); Public data receives the least.

### 2. Data Inventory (by Category)

| Category | Classification | Examples | Where Held |
|---|---|---|---|
| **Personal Information** | Confidential (credentials: Restricted) | Email, display name, phone number, GST number, password hash. | Primary application database. |
| **Customer Data** | Confidential | Account role/tier, usage statistics, billing/order history metadata. | Primary application database. |
| **Marketplace Data** | Restricted (credentials) / Confidential (order & listing data) | Marketplace API keys/tokens, order data received from a connected marketplace, publish status. | Primary application database; credentials isolated per Document 07. |
| **Product Data** | Confidential until published, then Public | Product name, description, images, price, category, HSN code, AI-generated marketplace copy. | Primary application database; media storage. |
| **Payment Data** | Restricted | Payment order references, transaction status. | SellAssist does **not** store cardholder data — payment card details are handled entirely by the payment processor (e.g., Razorpay); SellAssist holds only processor-issued references. |

### 3. Encryption

- **In transit:** all data between the client, SellAssist's backend, connected marketplaces, and the database is transmitted over TLS. Plaintext HTTP is not served in production.
- **At rest:** the primary database is encrypted at rest at the storage-engine level by the managed database provider.
- **Restricted-classification secrets** (password hashes, reset/verification tokens) are additionally hashed with a purpose-appropriate algorithm before storage — bcrypt for passwords (Document 02), SHA-256 for single-use tokens — so that even a full database compromise does not directly expose usable credentials.
- Marketplace and payment processor credentials are held as environment-scoped secrets (Document 06 §Secret Management), not stored in the primary database in plaintext.

### 4. Storage

- Production data is stored in a managed cloud database service; SellAssist does not operate self-managed database infrastructure.
- Data is logically separated by account — every query path is scoped to the authenticated account's own data unless the caller holds the in-product `ADMIN` role (Document 04 §2).
- Uploaded media (product images) is stored via the application's configured storage path and is not made publicly enumerable.

### 5. Backup

- The managed database provider's automated backup capability is relied upon as the primary backup mechanism (see Document 09 for backup cadence, RTO/RPO targets, and the current gap in independently tested restores).
- Backups are subject to the same access-control and encryption standards as production data — a backup is not a lower-security copy of the same Restricted/Confidential data.

### 6. Retention

- Customer Data and Product Data are retained for as long as the account is active, plus a defined post-closure grace period to allow for accidental-deletion recovery and any legally required retention (e.g., financial/tax record-keeping).
- Restricted-classification single-use tokens (password reset, email verification) are deleted/invalidated immediately upon use or expiry — they are not retained "for audit" beyond their functional purpose.
- Marketplace-issued credentials are retained only while the corresponding marketplace connection remains active; disconnecting a marketplace integration triggers deletion of its stored credential.
- Specific retention periods by data category are documented in SellAssist's public Privacy Policy (a customer-facing document; this policy governs the internal control, not the public disclosure text).

### 7. Deletion

- A customer may request deletion of their account and associated Personal Information. SellAssist processes such requests within the timeframe required by applicable law.
- Deletion removes or irreversibly anonymizes Personal Information; data that must be retained for a legal obligation (e.g., financial records) is retained only to the extent and duration that obligation requires, and is excluded from routine account data thereafter.
- Deletion requests are propagated to backups on the provider's normal backup-expiry cycle — a deleted record is not expected to be purged from historical backups instantaneously, and this is disclosed to the requester.
- Where a marketplace or payment processor independently retains data SellAssist transmitted to it (e.g., an order record on the marketplace's own systems), that retention is governed by that third party's own policy, not this one — SellAssist's obligation is to delete what it itself holds.

### 8. Data Sharing with Third Parties

- Data is shared with a third party (marketplace, payment processor, email provider, AI/ML provider) only to the extent necessary to provide the specific feature the seller has enabled (e.g., product data is sent to a marketplace only when the seller publishes to that marketplace).
- SellAssist does not sell Personal Information or Product Data to third parties.
- Every third-party processor is expected to provide a security and data-handling standard consistent with this policy; this is reviewed before a new third-party integration is added to the product.

### 9. Privacy

- SellAssist collects only the Personal Information necessary to provide the service (data minimization).
- Sellers are informed, via SellAssist's public Privacy Policy, what is collected and why.
- Marketplace Data received from a connected platform is used only for the purpose the seller connected that marketplace for (listing management, order sync) — not repurposed for an unrelated use without the seller's knowledge.

## Responsibilities

| Role | Responsibility |
|---|---|
| **CISO** | Owns this policy; owns the data classification scheme; approves any new category of data collection or new third-party data-sharing arrangement. |
| **Engineering** | Implements classification-appropriate encryption, access scoping, and deletion mechanics described above. |
| **All Personnel** | Handles data according to its classification level; does not export or copy Confidential/Restricted data outside authorized systems (e.g., into a personal spreadsheet for "convenience"). |

## Review Schedule

Reviewed annually, and immediately upon: a new data category being introduced (e.g., a new marketplace integration bringing a new data type), a change in applicable privacy law, or a Document 03 incident involving data exposure.
