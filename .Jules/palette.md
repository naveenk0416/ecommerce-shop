## 2025-06-08 - Keyboard Navigation for Hover-Revealed UI Elements
**Learning:** Tailwind classes like `opacity-0 group-hover:opacity-100` are frequently used to hide action buttons until a parent element is hovered. However, this pattern completely breaks keyboard navigation because screen reader/keyboard-only users never trigger the hover state. The elements receive focus, but remain visually invisible (`opacity-0`), creating a confusing, inaccessible experience.
**Action:** Always pair `group-hover` reveal utilities with focus-aware equivalents. If the action is a single button, use `focus-visible:opacity-100`. If it's a container of multiple actions (like a div wrapping buttons), use `focus-within:opacity-100`. Apply this principle consistently to all interactive elements revealed on hover.
